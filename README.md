# Hikari Mini App

![Версия 0.3.0](https://img.shields.io/badge/version-v0.3.0-61DAFB)

Интерфейсы участника и администратора клуба: React + TypeScript + Vite, React Router,
TanStack Query и TanStack Table. Тёмная тема по умолчанию, красный акцент,
левое меню и общие таблицы. На узком экране меню открывается как шторка,
таблицы прокручиваются горизонтально. Светлая тема включается в верхней панели.

Под пунктами меню показаны дата и версии компонентов этой сборки. При смене
версии в документации одновременно обновите `hikariRelease` и `version` в
[package.json](package.json), а также версию miniapp в lock-файле.

## Режим участника

В Telegram откройте «Панель клуба» в чате с ботом. В «Мероприятиях»
доступны вкладки «Предстоящие», «Я зарегистрирован» и «Все встречи».
«Все встречи» по умолчанию показывает более новые встречи первыми.
Под анонсом расположены красная кнопка «Зарегистрироваться» и отдельный выбор
напоминания. Кнопка «Уведомление» раскрывает варианты на всю ширину блока.
Исходный интервал — 60 минут. Явный выбор «Без уведомления»
сохраняется для следующих встреч. Если сохранённый интервал уже
недоступен, запись оформляется без напоминания,
а прежняя настройка остаётся для будущих встреч. До начала можно изменить
напоминание или отменить запись.

После встречи зарегистрированный участник может отметить посещение.
Сохраняется первый ответ из бота или miniapp. «Мой профиль» содержит анкету
и настройку предложений об отзыве. В «Отзывах» можно в любое время оставить
общий отзыв, просмотреть и удалить свои отзывы. Отзыв о встрече отправляется
из её карточки после завершения, если у участника есть действующая запись
и встреча не отменена.

Администратор переключается между режимами в боковом меню. На локальном
стенде откройте `/events` с обычным dev-входом администратора.

В открытом сезоне «Тайный Санта» появляется внизу списка разделов бокового
меню участника. Рядом с пунктом меню идёт отсчёт «До конца записи»,
а после окончания записи или утверждения жеребьёвки — «До итоговой встречи».
Отсчёт показывает полные дни, а когда остаётся меньше суток — часы и
минуты в формате ЧЧ:ММ. Когда встреча наступает, меню показывает дату обмена.
При подтверждённой отмене записи сохранённые пожелания
подставляются в форму повторной записи. После утверждения жеребьёвки
участник видит своего подопечного со ссылкой на Telegram рядом с именем,
меняет ответ о присутствии и отдельно
сохраняет описание подарка до 2000 символов. На вопрос о готовности можно
ответить «Подарок готов», «Подарок заказан (в пути)» или «Нет».
До первого ответа в форме выбрано «Нет». В карточке администратора
этому состоянию соответствует «Не подготовил».
В `/admin/santa` видны номер сезона, таблица участников с карточками
и редактор черновика жеребьёвки. В карточке сразу видны имя подопечного,
заполненное описание подарка и ссылка на Telegram, если она доступна.
Из карточки можно исключить участника. В окне исключения есть ссылка на его Telegram,
а после утверждения жеребьёвки сразу видны предложенные пары и готовность
подарков. В редакторе жёлтым отмечены дарители с изменившимся подопечным,
а раскрытые пожелания перемещаются вместе с человеком. На локальном стенде
можно переключать тестовые профили, просматривать их уведомления и сбросить
сезон, чтобы начать новый с прежними настройками.
[Локальная проверка «Тайного Санты»](https://github.com/jpegMushrum/hikari-secretary/blob/main/docs/santa-testing.md).

«Выборы маскота» доступны в `/admin/mascot` администратору и в `/mascot`
участникам после открытия приёма. Участники подают концепты, подтверждают
готовность к туру и оценивают карточки. Администратор модерирует заявки,
может открыть итоги для проектора на `/admin/mascot/screen` и отдельным
действием публикует их в режиме участника. На диаграмме каждого тура видно
место и процент лайков. Название открывает анонимную карточку концепта
с изображениями.
[Правила и локальная проверка выборов](https://github.com/jpegMushrum/hikari-secretary/blob/main/docs/mascot-election.md).

## Запуск в Docker

В корне интеграционного репозитория подготовьте `targets.json` по
`targets.example.json` и `.env` по `.env.example`. Для полного стека
укажите в корневом `.env` токен тестового бота и его `ADMIN_IDS`.

```powershell
docker compose -f docker-compose.bot-local.yml up -d --build
```

Для работы только с браузерной панелью и backend укажите сервис
`miniapp` в конце той же команды.

Открыть **http://localhost:5173**. Это самостоятельный локальный стек:
PostgreSQL → миграции → Go API → gateway для браузерного входа → miniapp,
а также тестовый Telegram-бот. Имя проекта — `hikari-miniapp-dev`.
PostgreSQL создаёт базу `hikari_dev` при инициализации тома. После применения
миграций данные можно создавать через бота или miniapp. Фоновые задачи бота
отправляют публикации в цели, заданные в корневом `targets.json`.

```powershell
docker compose -f docker-compose.bot-local.yml ps
docker compose -f docker-compose.bot-local.yml logs --tail=100 backend gateway miniapp
docker compose -f docker-compose.bot-local.yml down
```

`down` сохраняет данные. Не добавляйте `-v`, если хотите сохранить созданные
встречи. UI опубликован только на `127.0.0.1:5173`, dev PostgreSQL — на
`127.0.0.1:55439`. Не используйте этот compose для публичного стенда.

## Разработка с обновлением кода

После запуска Docker-стенда, из `miniapp/`, Node.js 24:

```powershell
npm ci
npm run dev
```

Vite: **http://127.0.0.1:5174**, с прокси `/api` к стенду на 5173.
Docker-страница на 5173 показывает последнюю сборку, Vite на 5174 — текущий код.
Обновить Docker-версию: повторить `up -d --build` из корня.

## Что работает

- Мероприятия: поиск по названию или ID, статусы, период, сортировка, страницы; карточка,
  статистика, список регистраций с фильтром пропусков, просмотр анонса,
  список анонсов и черновиков из бота, предпросмотр, настройка мероприятия
  и целей, немедленная или отложенная публикация, отмена с подтверждением.
- Участники: поиск по имени, Telegram username (с `@` или без), внутреннему ID
  или Telegram ID, фильтры по гражданству и ИТМО, посещения, последний визит,
  число отзывов и переход к ним.
- Отзывы: поиск по названию или ID мероприятия, имени, Telegram username
  или ID автора, а также по ID отзыва. Фильтр типа, карточка отзыва и
  переход к встрече. Ссылки на отзывы конкретного мероприятия или участника
  задают точный фильтр, который можно снять кнопкой «Сбросить».
- ИИ: общие с ботом настройки уровня и комментария, состояние подключения,
  история заданий с фильтром статуса генерации и сортируемой колонкой
  «Публикация» и количеством сохранённых версий. Карточка
  `/admin/ai/history/:id` показывает статус публикации,
  назначенное время и предпросмотр сохранённого сообщения с
  форматированием Telegram. Для архивных заданий без связанной публикации
  показывается сохранённый материал с исходным названием темы. Если у
  задания несколько версий, поле «Версия материала» позволяет выбрать текущую
  или одну из прежних версий. При выборе текущей версии карточка показывает
  предпросмотр связанной публикации, если она есть. Кнопка «Загрузить более
  ранние версии» подгружает следующую страницу.
  Ключи остаются на сервере. Настройки и история доступны и без ключа.
  На странице `/admin/ai` в блоке «Автоматическая генерация» кнопка
  «Отменить выход поста» снимает с отправки последний поставленный в очередь
  ИИ-пост независимо от даты и способа запуска. Отмена доступна после
  постановки поста в очередь, пока все его доставки ожидают отправки или
  повторной попытки. Настройка ежедневной генерации сохраняется.
  Кнопка «Выключить автогенерацию» останавливает её на следующие
  дни и сохраняет сегодняшний пост. Кнопка «Включить автогенерацию»
  возобновляет ежедневную генерацию. Настройка сохраняется после перезапуска.
  Кнопка «Поставить новую генерацию в очередь» использует сохранённые уровень
  JLPT и комментарий. Она доступна при выключенной автогенерации. У
  ближайшего ожидающего ИИ-поста сохраняются время отправки и цели, а
  сообщение обновляется после успешной генерации. Если таких постов нет,
  новый материал ставится на ближайшее время по расписанию или на отправку
  сразу после генерации, если время не задано. Рядом с кнопкой отображаются
  ход генерации и ошибки. Кнопка «На главную» в карточке возвращает в раздел ИИ.
- Таблицы: серверная пагинация/сортировка/фильтрация, параметры в URL,
  скрываемые и переставляемые колонки в localStorage с привязкой к администратору,
  состояния загрузки/ошибки/пустой выборки. Время отображается по Москве.

В таблицах мероприятий и черновиков, публикаций, участников, отзывов и
истории ИИ колонка «ID» видна по умолчанию. Её можно скрыть в меню «Колонки».
В карточке мероприятия таблица участников показывает внутренний ID человека.

Название текущего раздела в верхней панели ведёт на его начальную страницу.
Ссылка «На главную» в карточках мероприятий и отзывов ведёт к списку
соответствующего раздела.

## Архитектура и доступ

```text
src/app/       оболочка, реестр модулей, маршруты, обработка ошибок
src/modules/   экраны events / publications / people / feedback / ai
src/shared/    HTTP-клиент, контракты API, таблица, общие элементы
deploy/        nginx для обычной сборки (Admin API и Member API)
dev/           локальный gateway, nginx override и проверки
```

Раздел добавляется в `src/app/modules.tsx`; меню и основные маршруты строятся
из реестра. Навигация не привязана к фиксированному числу разделов.
Данные принадлежат backend, все бизнес-правила проверяет сервер.
Фронтенд обращается к `/api/v1/admin/` и `/api/v1/member/`.
Контракт описан в [OpenAPI backend](https://github.com/jpegMushrum/hikari-secretary-backend/blob/main/openapi/openapi.yaml).

Локальный gateway подписывает свежий `initData` **заведомо фиктивным**
токеном для администратора `123456789`. Go API проходит обычную проверку
подписи и роли; обхода авторизации в backend нет. Gateway ограничивает
Host/Origin и проксирует Admin API и Member API. Он не включён в конечный образ
miniapp или production compose. Общедоступный стенд должен использовать
настоящую Telegram-аутентификацию, а не этот локальный gateway.

При запуске с Telegram launch data загружается SDK до первого API-запроса;
HTTP-клиент передаёт `Telegram.WebApp.initData`. В обычном локальном браузере
SDK не загружается. Для запуска в Telegram нужны публичный HTTPS-адрес
и настройка бота. См. [инструкцию production](https://github.com/jpegMushrum/hikari-secretary/blob/main/docs/production.md).

## Сообщение в бота → настройка в панели

1. Администратор отправляет или пересылает сообщение либо фотоальбом боту.
2. Бот сохраняет общий черновик, исходные entities и rich_message, затем
   показывает номер черновика и варианты продолжения.
3. При HTTPS-адресе панели «Открыть черновик в miniapp» открывает этот черновик
   через Telegram WebApp. «Остаться в чате» открывает предпросмотр и настройки
   публикации в Telegram. Без адреса панели доступен вариант в чате.
4. В панели можно открыть тот же черновик и через «Мероприятия → Создать
   мероприятие» или «Все анонсы и черновики».
5. В форме «Настройки» задаются регистрация, название и даты встречи, цели
   и время публикации. Настройки мероприятия и целей сохраняются одной
   транзакцией. Для привязанного мероприятия переключатель регистрации
   в форме заблокирован.
   Отправка выполняется ботом через существующую очередь backend.

Встроенного редактора текста больше нет: Telegram остаётся местом подготовки
сообщения. Настройка в панели не перезаписывает текст, entities, rich_message
или вложения. При отправке форма сначала сохраняет настройки, затем ставит
публикацию в очередь отдельным запросом. Если второй запрос завершился
ошибкой, проверьте статус публикации перед повтором.
Уже отправленное сообщение через эту форму не изменяется.

Предпросмотр поддерживает Telegram entities (UTF-16 offsets), основные rich
текстовые блоки, списки, таблицы, цитаты, раскрываемые блоки, ссылки, кнопки
URL и фотографии. HTML не исполняется; опасные схемы ссылок отбрасываются.
Видео, аудио, карты, действия callback-кнопок и другие неподдерживаемые
элементы помечаются как доступные в оригинале Telegram. Точное совпадение
вёрстки с Telegram не обещается. Старые rich-фотографии без локальной копии
также имеют явную заглушку.

Фото читаются с авторизацией через `/publications/{id}/media/{position}`,
затем показываются как временный blob URL; токен Telegram/пути файлов
не попадают в URL браузера. Бот скачивает фото rich-сообщений для preview;
сбой скачивания не блокирует создание и отправку исходного rich message.
Фото теперь сохраняются после отправки/отмены для истории. Автоматического
retention пока нет; общий media volume нужно учитывать при backup/очистке.

В общем списке участников username открывает профиль в Telegram. В таблице
участников встречи при отсутствии username ссылка использует Telegram ID.
Работа такой ссылки зависит от клиента и доступности аккаунта.
Нажмите заголовок любой колонки, чтобы отсортировать весь отфильтрованный
список. Повторное нажатие меняет направление сортировки.
Порядок колонок настраивается в меню «Колонки». Перетащите строку за ручку или
выберите ручку с клавиатуры и нажмите стрелку вверх или вниз. При
перетаскивании к верхнему или нижнему краю меню список прокручивается внутри.
Нажатие вне меню или Esc закрывает его. Исходный порядок можно восстановить
в том же меню.

## Проверки без браузера

```powershell
npm run build
npm test
npm run test:gateway
node dev/smoke.mjs
```

Unit-тесты UI выполняются в jsdom (без запуска браузера). Проверяются
таблица, порядок колонок и запросы, настройка черновика без изменения текста,
UTF-16 entities, безопасные ссылки и rich preview, настройки ИИ,
заголовок авторизации, форматирование. Gateway-тесты проверяют подпись и
изоляцию запросов. Smoke-скрипт читает HTML, assets и реальные API локального
стенда; проверяет SPA fallback и запрет чужого Origin.

Backend unit + PostgreSQL tests из `backend/`:

```powershell
go test ./...
$env:TEST_DATABASE_URL = 'postgres://hikari_dev:local_dev_only@127.0.0.1:55439/hikari_dev?sslmode=disable'
try { go test -count=1 -tags=integration ./... }
finally { Remove-Item Env:TEST_DATABASE_URL }
```

Интеграционные тесты API и миграций используют временные схемы и сами
применяют миграции. Учётная запись тестов должна иметь право CREATE SCHEMA.

## Локальный стенд с тестовым ботом

Из корня интеграционного репозитория:

```powershell
docker compose -f docker-compose.bot-local.yml up -d --build
```

Compose использует токен тестового бота и `ADMIN_IDS` из корневого `.env`,
а цели берёт из корневого `targets.json`. Бот и miniapp через backend работают
с одной базой `hikari_dev`.

Администратор отправляет или пересылает материал в личный чат тестового бота.
После сохранения бот показывает «Скопировать ссылку на черновик». Вставьте
ссылку в браузер на компьютере, где запущен стенд. Список черновиков также
доступен по адресу [localhost:5173/admin/events/drafts?status=draft](http://localhost:5173/admin/events/drafts?status=draft).
Новые фото сохраняются в общем `data/media`; для просмотра старых фото нужны
соответствующие локальные файлы.

Compose сам задаёт боту `APP_ENV=development` и
`MINIAPP_URL=http://localhost:5173`. Кнопка WebApp в Telegram используется
на стендах с HTTPS.

## Таблица участников встречи

В таблице участников встречи «Время регистрации» и «Время отмены» показаны
в отдельных скрываемых колонках. При отсутствии даты отображается тире.
Отметка посещения отображается в колонке «Был на встрече». В колонке и
фильтре «Нужен пропуск» используются варианты «Нужен» и «Не нужен».

В таблице участников встречи меню «Колонки» содержит настройку
«Сокращённый вид» для статуса, сохраняемую для администратора.
Короткий статус показывает цветной индикатор с доступным названием и
подсказкой; зарегистрирован — зелёный, отменён — серый. Колонки
«Гражданин РФ» и «Студент ИТМО» доступны постоянно; скрыть их можно
обычными переключателями видимости в меню «Колонки».
Неизвестные значения не считаются ответом «Нет»: при недостатке сведений
таблица показывает «Уточнить данные». Серверный фильтр пропусков сохраняет
консервативную политику и включает таких участников. Сброс колонок также
сбрасывает сокращённый вид.
