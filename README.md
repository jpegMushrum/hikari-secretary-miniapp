# Hikari Mini App · первая браузерная версия

Административный интерфейс клуба: React + TypeScript + Vite, React Router,
TanStack Query и TanStack Table. Тёмная тема по умолчанию, красный акцент,
левое меню и общие таблицы. На узком экране меню открывается как шторка,
таблицы прокручиваются горизонтально. Светлая тема включается в верхней панели.

## Запуск в Docker

Из корня **интеграционного** репозитория:

```powershell
docker compose -f docker-compose.bot-local.yml up -d --build
```

Открыть **http://localhost:5173**. Это самостоятельный локальный стек:
PostgreSQL → миграции → Go API → gateway для браузерного входа → miniapp,
а также настоящий тестовый бот из корневого `.env`.
Проект `hikari-miniapp-dev`, volumes и порты сохранены. База выбирается
через `LOCAL_DATABASE_NAME` (по умолчанию существующая копия импорта
`hikari_bot_local_20261117`). Эта база должна быть подготовлена заранее;
демоданные автоматически не создаются. Workers бота включены и отправляют
публикации в настроенные цели. Не используйте здесь production-токен.

```powershell
docker compose -f docker-compose.bot-local.yml ps
docker compose -f docker-compose.bot-local.yml logs --tail=100 backend gateway miniapp
docker compose -f docker-compose.bot-local.yml down
```

`down` сохраняет данные. Не добавляйте `-v`, если хотите сохранить созданные
встречи. UI опубликован только на `127.0.0.1:5173`, dev PostgreSQL — на
`127.0.0.1:55439`. Не используйте этот compose для публичного стенда.

## Разработка с обновлением кода

После запуска Docker-стенда, из `miniapp/`, Node.js 24:

```powershell
npm ci
npm run dev
```

Vite: **http://127.0.0.1:5174**, с прокси `/api` к стенду на 5173.
Docker-страница на 5173 показывает последнюю сборку, Vite на 5174 — текущий код.
Обновить Docker-версию: повторить `up -d --build` из корня.

## Что работает

- Мероприятия: поиск, статусы, период, сортировка, страницы; карточка,
  статистика, список регистраций с фильтром пропусков, просмотр анонса,
  список анонсов и черновиков из бота, предпросмотр, настройка мероприятия
  и целей, немедленная или отложенная публикация, отмена с подтверждением.
- Участники: поиск, гражданство/ИТМО, посещения, последний визит, число
  отзывов и переход к ним.
- Отзывы: таблица, фильтры типа/мероприятия/автора, детали и переход к встрече.
- ИИ: общие с ботом настройки уровня и комментария, состояние подключения,
  история заданий с фильтром статуса и просмотром материала. Ключи не
  передаются frontend; без ключа настройки и история доступны.
- Таблицы: серверная пагинация/сортировка/фильтрация, параметры в URL,
  скрываемые и переставляемые колонки в localStorage с привязкой к администратору,
  состояния загрузки/ошибки/пустой выборки. Время отображается по Москве.

## Архитектура и доступ

```text
src/app/       оболочка, реестр модулей, маршруты, обработка ошибок
src/modules/   экраны events / people / feedback / ai
src/shared/    HTTP-клиент, контракты API, таблица, общие элементы
deploy/        nginx для обычной сборки (прямой защищённый Admin API)
dev/           только локальный gateway, nginx override, seed и проверки
```

Раздел добавляется в `src/app/modules.tsx`; меню и основные маршруты строятся
из реестра. Навигация не привязана к фиксированному числу разделов.
Данные принадлежат backend, все бизнес-правила проверяет сервер.
Фронтенд не подключается к PostgreSQL и не получает BOT_SERVICE_TOKEN.

Локальный gateway подписывает свежий `initData` **заведомо фиктивным**
токеном для администратора `123456789`. Go API проходит обычную проверку
подписи и роли; обхода авторизации в backend нет. Gateway ограничивает
Host/Origin и проксирует только Admin API. Он не включён в конечный образ
miniapp или production compose. Общедоступный стенд должен использовать
настоящую Telegram-аутентификацию, а не этот локальный gateway.

При запуске с Telegram launch data загружается SDK до первого API-запроса;
HTTP-клиент передаёт `Telegram.WebApp.initData`. В обычном локальном браузере
SDK не загружается. HTTPS, настройка окружения, тема/размеры WebView и ручная
проверка устройств нужны до Telegram-релиза; на прод эта версия не выложена.

## Сообщение в бота → настройка в панели

1. Администратор отправляет/пересылает сообщение или фотоальбом боту.
2. Бот сохраняет общий черновик, исходные entities и rich_message.
3. При заданном `MINIAPP_URL=https://club.example` в окружении бота рядом
   с обычными кнопками появляется «Продолжить в панели» для этого черновика.
   URL должен быть HTTPS origin, без пути, query и fragment. Без настройки
   кнопка не появляется, существующий flow бота работает как раньше.
4. В панели можно открыть тот же черновик и через «Мероприятия → Создать
   мероприятие» или «Все анонсы и черновики».
5. Справа задаются регистрация, название и даты встречи, цели и время
   публикации. Настройки события/целей сохраняются одной транзакцией.
   Отправка выполняется ботом через существующую очередь backend.

Встроенного редактора текста больше нет: Telegram остаётся местом подготовки
сообщения. Настройка в панели не перезаписывает текст, entities, rich_message
или вложения. Сохранение настроек и постановка в очередь — два явных шага;
при ошибке второго шага сохранённый черновик остаётся доступен для повтора.
Уже отправленное сообщение через эту форму не изменяется.

Предпросмотр поддерживает Telegram entities (UTF-16 offsets), основные rich
текстовые блоки, списки, таблицы, цитаты, раскрываемые блоки, ссылки, кнопки
URL и фотографии. HTML не исполняется; опасные схемы ссылок отбрасываются.
Видео, аудио, карты, действия callback-кнопок и другие неподдерживаемые
элементы помечаются как доступные в оригинале Telegram. Точное совпадение
вёрстки с Telegram не обещается. Старые rich-фотографии без локальной копии
также имеют явную заглушку.

Фото читаются с авторизацией через `/publications/{id}/media/{position}`,
затем показываются как временный blob URL; токен Telegram/пути файлов
не попадают в URL браузера. Бот скачивает фото rich-сообщений для preview;
сбой скачивания не блокирует создание и отправку исходного rich message.
Фото теперь сохраняются после отправки/отмены для истории. Автоматического
retention пока нет; общий media volume нужно учитывать при backup/очистке.

В таблице участников встречи есть Telegram-ссылка. Без username используется
переход по user ID; его работа зависит от клиента и доступности аккаунта.
Порядок колонок меняется drag-and-drop в заголовках/меню или кнопками
«Поднять/Опустить» в меню (включая телефон); есть сброс к исходному порядку.

## Проверки без браузера

```powershell
npm run build
npm test
npm run test:gateway
node dev/smoke.mjs
```

Unit-тесты UI выполняются в jsdom (без запуска браузера). Проверяются
таблица, порядок колонок и запросы, настройка черновика без изменения текста,
UTF-16 entities, безопасные ссылки и rich preview, настройки ИИ,
заголовок авторизации, форматирование. Gateway-тесты проверяют подпись и
изоляцию запросов. Smoke-скрипт читает HTML, assets и реальные API локального
стенда; проверяет SPA fallback и запрет чужого Origin.

Backend unit + PostgreSQL tests из `backend/`:

```powershell
go test ./...
$env:TEST_DATABASE_URL = 'postgres://hikari_dev:local_dev_only@127.0.0.1:55439/hikari_dev?sslmode=disable'
try { go test -count=1 -tags=integration ./... }
finally { Remove-Item Env:TEST_DATABASE_URL }
```

Интеграционные тесты API и миграций используют временные схемы и сами
применяют миграции. Учётная запись тестов должна иметь право CREATE SCHEMA.

## Локальный стенд с тестовым ботом и импортированной базой

Из корня интеграционного репозитория:

```powershell
docker compose -f docker-compose.bot-local.yml up -d --build
```

Compose использует токен тестового бота и ADMIN_IDS из корневого `.env`.
Бот и miniapp работают с одной базой `hikari_bot_local_20261117` внутри
dev PostgreSQL. Это отдельная копия ранее импортированной базы, созданная
17 ноября 2026: 2 участника, 16 мероприятий, 2 отзыва, 11 публикаций.
Исходная база и демонстрационная `hikari_dev` сохранены; синхронизации
с исходной базой нет. Автоматического demo seed нет.

База-копия уже подготовлена на текущей машине. На новой машине её нужно
сначала создать и восстановить из дампа: этот Compose сам SQLite не импортирует.
Локальный дамп находится в `data-miniapp-backup/imported-20261117.dump`
(приватные данные, каталог исключён из Git). Не удаляйте Docker volume
командой `down -v`, если хотите сохранить эту копию.

Администратор пересылает сообщение в личный чат тестового бота. Бот
создаёт черновик через backend и отвечает обычной карточкой черновика.
Откройте `http://localhost:5173/admin/events/drafts?status=draft` и обновите
страницу после отправки. Выберите черновик для предпросмотра и настройки
мероприятия. Новые фото сохраняются в общем `data/media`; старые фото
отображаются только при наличии соответствующих локальных файлов.

`MINIAPP_URL` здесь пустой: HTTP localhost открывается вручную в браузере,
кнопка Telegram WebApp требует отдельного HTTPS адреса.
`BOT_BACKGROUND_WORKERS_ENABLED=true` в локальном Compose включает публикации,
напоминания и уведомления для полного тестирования. Постановка в очередь
приводит к реальной отправке в выбранные Telegram-цели. Перед первым
включением проверены импортированные очереди: старые публикации не имеют
статуса scheduled, outbox пуст. Для временной остановки фоновых отправок
можно установить false и пересоздать контейнер бота.

На странице мероприятий вкладка «Черновики» заменяет «Отменённые»;
отменённые доступны через фильтр. «Все встречи» включает черновики,
в том числе без даты/мероприятия, и ведёт из них в предпросмотр публикации.
Backend `/event-workspace` обеспечивает общую серверную пагинацию,
поиск и сортировку; настроенное мероприятие черновика не дублируется.
Фильтр дат исключает черновики без даты. Статус отправки на странице
публикации обновляется автоматически, пока она находится в очереди.

Остановить только тестового бота:

```powershell
docker compose -f docker-compose.bot-local.yml stop bot
```

Отдельный режим с автоматическим demo seed удалён. Для работы без бота
можно запускать только нужные сервисы этого же файла, например `up -d miniapp`;
если бот уже запущен, сначала выполните `stop bot`.

## Следующие шаги

Совместная визуальная проверка мобильной и широкой версии; затем ранний
запуск в Telegram для администраторов. Далее — замена содержимого существующего
черновика через бота, уточнённые репосты, дополнительные типы preview,
защита незавершённых форм и остальные согласованные сценарии.
Визуальные проверки в браузере и Telegram в этом этапе не выполнялись.
Общий roadmap: `../docs/miniapp-plan.md` интеграционного репозитория.


В таблице участников меню «Колонки» содержит настройку
«Сокращённый вид» для статуса, сохраняемую для администратора.
Короткий статус показывает цветной индикатор с доступным названием и
подсказкой; зарегистрирован — зелёный, отменён — серый. Колонки
«Гражданин РФ» и «Студент ИТМО» доступны постоянно; скрыть их можно
обычными переключателями видимости в меню «Колонки».
Неизвестные значения не считаются ответом «Нет»: при недостатке сведений
таблица показывает «Уточнить данные». Серверный фильтр пропусков сохраняет
консервативную политику и включает таких участников. Сброс колонок также
сбрасывает сокращённый вид.
