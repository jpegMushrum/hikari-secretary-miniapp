# Miniapp

В составе платформы применяй также корневой `AGENTS.md`.

## Реализация

- React/TypeScript miniapp использует backend API. Не дублируй серверные
  правила доступа и бизнес-логику в браузере. Dev-вход остаётся локальным.
- Разделы и навигация должны расширяться без переписывания оболочки.
  Пользовательские разделы вводятся отдельно от текущих административных.
- Стиль: близко к мобильному Telegram, минимум цветов и визуальных слоёв,
  красный акцент клуба, логотип 光, тёмная и светлая темы.
  Не добавляй декоративные карточки и общие рекламные тексты без необходимости.
- Выделяй положительные статусы зелёным в обеих темах и сохраняй текстовую
  подпись состояния.
- Сохраняй настраиваемые колонки, серверные фильтры, сортировку и пагинацию.
- Задавай явный `gap` между соседними элементами строки, в том числе при
  переносе кнопок на новую строку. Отделяй действия от поясняющего текста.
  Изображение и его подпись объединяй в одну группу с общей границей по краю.
- Для просмотра объекта из списка используй именованную карточку или кнопку
  просмотра. Нативный раскрывающийся список оставляй для короткого выбора
  значений. У интерактивных элементов сохраняй управление с клавиатуры.
- Рядом с именем участника показывай ссылку на его Telegram, если профиль
  доступен этой аудитории. На анонимных карточках и в публичных итогах выборов
  сохраняй анонимность автора.
- Сообщения готовятся в Telegram; miniapp показывает rich preview и настройки
  публикации. Не добавляй rich-редактор без отдельного решения.
- Учитывай узкие экраны, нативные поля iOS, доступность подписей и клавиатурного
  управления. Не заменяй содержимое без обработки загрузки и ошибок.

## Проверки

- Из этого каталога: `npm run build` и `npm test` для изменений приложения.
- При изменении локального gateway дополнительно: `npm run test:gateway`.
- Тестируй пользовательское поведение, права, обработку ошибок и контракт API;
  не создавай тесты, лишь сравнивающие CSS с его же реализацией.
- DOM-тесты не доказывают корректность отрисовки Safari или Telegram WebView.
  Указывай отдельно, какие визуальные и аппаратные проверки не выполнены.
- Соблюдай ограничения пользователя на браузер и работу с реальным ботом.
  Не запускай production-развёртывание ради визуальной проверки.

## Документация и делегирование

- Изменённые сценарии, конфигурацию и команды отражай в README и профильных
  документах. Согласованные планы платформы находятся в корневых `docs/`.
- После существенной реализации поручай субагентам ревью diff и сверку
  документации; назначай непересекающиеся файлы для редактирования.
- Для документации используй `gpt-6.2-sol` с уровнем `low`.
- Для обычного ревью используй `gpt-6.2-sol` с уровнем `medium`.
- Только для сложного ревью миграций, авторизации или очередей используй `gpt-6.2-astra` с уровнем `medium`.
- Если выбранная модель недоступна, сообщи об этом и выполни задачу главным агентом. Другую модель используй только по указанию пользователя.
- В начале цикла укажи целевую версию в CHANGELOG по правилам корневого AGENTS.md.
